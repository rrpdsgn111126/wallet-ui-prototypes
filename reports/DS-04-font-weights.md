# DS-04 — аудит насыщенности текста до 20 px

- Ветка: `work/design-system`.
- Исходная точка (до изменения весов): [`72fd74302326fe9a3c7b53bae000eaff18a7ddd3`](https://github.com/rrpdsgn111126/wallet-ui-prototypes/commit/72fd74302326fe9a3c7b53bae000eaff18a7ddd3).
- Диапазон: `font-size ≤ 20 px` включительно, как запрошено. Крупные размеры, типографическая графика и печатные формы исключены.
- Нормативные правила: только `docs/UI_PATTERNS.md`; здесь хранится отчёт об изменениях.

## 1. Факт: библиотека до нормализации

Playwright снял фактические `getComputedStyle` у компонентов UI Kit (включая вложенные банковские образцы) через `showcase/typography.js`. **125 уникальных комбинаций** в 42 карточках (из них текст есть в 38):

| Вычисленная насыщенность | Количество сочетаний |
|---|---:|
| 400 | 42 |
| 500 | 43 |
| 600 | 40 |
| 300 / 450 / 550 / 650 / 700 / 800 / 850 / 900 | 0 |

Это количество **комбинаций стиля, сгруппированных по компонентам**, а не частота встречаемости текстовых элементов на экране. Не следует по нему судить о долях символов или всей продукционной сборки. Исходный GitHub Actions: [workflow run 44314301775](https://github.com/rrpdsgn111126/wallet-ui-prototypes/actions/runs/44314301775).

## 2. Кодовые исключения, не видимые в библиотеке

- `550` встречался у `.tf-history-desc b` (14 px) и `.tf-method-details b` (16 px) в банковском `legacy.html`. У них нет самостоятельной семантической роли между 500 и 600.
- `650` встречался у заголовка тестовой панели `#tf-qa-panel h2` (19 px).
- `700` использовался в нескольких текстовых контекстах с кеглями 10–20 px: суммы/значения в `.prcols b`, `.prtiles b`, `.sbp-calc .rl.tot b`, название `.prln`, элементы управляющей панели `.brand`, `.sideLabel`, `.stepBtn.active .num`.
- `700` также есть в графических символах `.mark .m`, `.tf-method-icon`, а иные нестандартные веса — в крупных (>20 px) заголовках, стрелках, брендинге и графике; это **не текущий объект изменения**.
- Обычные правила `font-weight: 400/500/600` уже доминировали. Полностью заменять компоненты и создавать новые типографические роли было бы неоправданно.

## 3. Нормализация

Для обычного текста ≤20 px: **400 — базовый; 500 — смысловой акцент; 600 — кнопка / заголовок / сильный акцент**.

- `550 → 500` в банковской истории и реквизитах метода.
- `650 → 600` у заголовка QA-панели (19 px).
- `700 → 600` в `.prln`, `.prcols b`, `.prtiles b`, `.sbp-calc .rl.tot b` в общем CSS **и его встроенной копии в прототипе**, а также `.brand`, `.sideLabel`, `.stepBtn.active .num` в банковской тестовой оболочке.
- Убрано конфликтующее раннее объявление 600 для `.tf-method-details b`: оба одноимённых правила теперь используют 500.
- Графические элементы, печать и кегли свыше 20 px не изменены.

**Итого:** 15 замен CSS-объявлений, считая дублированные стили внешнего CSS и `index.html`. Кроме них обновлены нормативное правило, JSON-политика типографики и автоматизированный аудит.

## 4. Постоянный аудит

- `node tests/design-system/font-weight-audit.mjs <url-ui-kit>` измеряет вычисленные стили в браузере и генерирует JSON-отчёт для каждого прогона.
- Скрипт отдельно проверяет явные CSS-насыщенности и разрешённые графические исключения; новые отклонения в обычном тексте ≤20 px приводят к ошибке CI.
- CI должен проверить 390/430/1440 px, снимки до/после, кликабельную библиотеку и не переносить изменения в `main` либо `work/prototype`.
- Изменения из этого отчёта не являются подтверждением того, что все тексты любого состояния живого приложения проверены: для скрытых модальных окон и сценариев требуется отдельный обход.
