# TransFi: UI alignment with alt.vu source components

**Visual authority:** `transfi-remittance/index.html`, the original archived alt.vu source.

**Scope:** SEPA and SWIFT flows, including both incoming bank details and outgoing configuration, recipient, review, processing and terminal states. No changes to transfer APIs, state machine, validation, or monetary formulas.

| TransFi | Original alt.vu component |
|---|---|
| Frame background / decorative top | `.view`, `.tint` |
| Back navigation and title | `.head .back .h1` |
| Scrollable content | `.wrap.tight` |
| Input, balance source | `.fld.w`, `.fld.g`, `.fi`, `.fl` |
| Bank currency/country/purpose picker | `.fld.w.net-pick` → `.view.ovl` with `.dim` + `.sheet`; `.box > .row > .ri + .rt + .rd` |
| Currency choice | `.seg` |
| Requirements, review | `.box .row .rt .rv` |
| Exchange and fee summary | `.tbl .rl` |
| Review summary | `.amt`, `.amsub` |
| Status indicator | `.hero`, `.okc`, native line-art SVG |
| Primary/secondary CTA | `.foot .btn`, `.btno` |

Bank-only CSS is located at `css/transfi-bank-altvu.css`, is scoped to `.phone.tf-phone` and loaded last by `transfi-remittance/legacy.html`. Do not change the original app-wide CSS or hand-draw new bank components unnecessarily.

**Acceptance:** same computed sizes as alt.vu where component shapes match (field height 68 px, CTA 52 px, title 20 px, box/table radius 20 px); no horizontal scrolling; all existing TransFi states render at 390 and 430 px; SWIFT config → recipient → review → processing works. Automated checks: `tests/bank-parity.mjs` / workflow `transfi-bank-parity.yml`.

## Канонический селектор — по экрану «Пополнение USDT → Сеть»

**Один канонический компонент в UI Kit:** [раздел «Канонический селектор: сеть, страна и валюта»](../ui-kit/index.html#selectors). Внутри **три автономных интерактивных поля** — сеть ([components/netsheet.html](../components/netsheet.html)), страна и валюта ([components/bankpicker.html](../components/bankpicker.html)). По умолчанию видимо лишь поле; шторка с вариантами появляется **после нажатия**. Полных экранов SEPA/SWIFT, их навбаров, сумм и реквизитов в этих образцах нет.

**Селектор валюты — общий**, а не «селектор SWIFT»: применяется в любом поддерживаемом сценарии, где пользователь должен выбрать валюту. Библиотечный образец намеренно назван «Валюта». Для реального списка валют и ограничений направления используется конфигурация соответствующего метода, а не жёсткий набор SWIFT.

Образцы страны и валюты используют исходные `uxPickerField()`, `uxRenderPicker()` и `uxChoosePicker()` из `legacy.html` по изолированному маршруту `?component=picker&kind=country|currency&embedded=1`. Это **та же рабочая реализация**, просто без остального экрана. Сеть использует исходную комбинацию `.fld.w.net-pick` и `.view.ovl .sheet.ns-sheet` из кошелька с интерактивным выбором.

Источники в исходном архиве alt.vu: `transfi-remittance/index.html`, извлечённые эталонные HTML-компоненты `components/netpick.html`, `components/netsheet.html`, исходные стили `css/alt-vu-wallet.css` (`.dim`, `.sheet`, `.grab`, `.sh2`, `.box`, `.row`, `.ri`, `.rt`, `.rd`).

- **Витрина:** поле само по себе, без названия метода, навбара, описательных карточек и заранее открытой модалки. Тап по полю → шторка; тап по строке → новое значение в том же поле; повторный тап снова открывает шторку. Закрытие по затемнению и Escape не меняет выбор.
- Триггер: стандартное поле `.fld.w` с `.fi` 40×40, `.fl`, стрелкой. Для страны внутри серого круга рисуется **круглая векторная иконка флага 24×24**, а не emoji, текстовый код страны или дополнительный вложенный серый круг.
- Модалка: отдельный экран `.view.ovl.on`; **подложка** `.dim` с `z-index:4`, чёрный фон и `opacity:.4`; **панель** `.sheet` с `z-index:5`, оригинальной верхней тенью, радиусами 24 px, `.grab` и заголовком `.sh2`. Панель обязана быть визуально **над** затемнением, иначе поверх неё появляется серый фильтр.
- Список: **единая белая** `.box`, несколько строк `.row` с внутренними разделителями; **не** отдельные карточки с зазорами и закруглёнными углами. Левая иконка `.ri` 32×32, надпись `.rt`, справа **штатный круглый селектор** `.rd` 24×24. Выбранное — только `.rd.on` с `box-shadow: inset 0 0 0 7px var(--brand)`. Не рисовать галочку, зелёную рамку строки или вторую модель радиоэлемента.
- Поведение: выбор строки меняет значение триггера и закрывает шторку, поля форм сохраняются; тап по затемнению и Escape закрывают без выбора; стрелки клавиатуры / Home / End переводят фокус по строкам. Не разрешать выбор неподдерживаемых стран для SEPA.
- Все банковские селекторы `inCurrency`, `outCurrency`, `country`, `purpose` работают через общий `uxRenderPicker` в `transfi-remittance/legacy.html`. Изменения не затрагивают оригинальную шторку сети USDT.
- Векторные флаги `DE, FR, NL, ES, GB, US` встроены без сторонних зависимостей; в каждой строке списка и в выбранном поле должна быть видна именно графика флага. `aria-checked` выставляется одному пункту, а внешний вид определяется только `.rd.on`.

**Регрессия:** `tests/bank-qa/smoke.py` проверяет поведение и вычисленный `z-index`, стили списка, размер и состояние радиоэлементов, реальные SVG-флаги и клики без `force`. `tests/bank-parity.mjs` проверяет общую визуальную согласованность на 390/430 px. Использовать GitHub Actions `prototype-playwright.yml` и `transfi-bank-parity.yml` перед приемкой.

## Каноническое поле списания, валюты и мобильная шапка (16.11.2026)

**Проверенные источники:** исходный компонент [components/fld.html](../components/fld.html) (состояние «Только чтение, серое»), [components/amount.html](../components/amount.html) (монета у суммы), `css/alt-vu-wallet.css` (размеры `.fld`, `.fi`, `.head`). Актуальные экземпляры живых полей в [components/bankfields.html](../components/bankfields.html), [UI Kit](../ui-kit/index.html#bankfields); единственный источник их разметки и логики — `transfi-remittance/legacy.html`. Не подменять оригинал произвольно созданными собственными стилями.

### 1. «Со счёта alt.vu» — один readonly-вариант

- Разметка: `<div class="fld g tf-field tf-source"><div class="fi">Логотип alt.vu</div><div class="fl"><i>Со счёта alt.vu</i><b>Доступно 4 812.60 $</b></div></div>`.
- Контейнер `.fld.g`: 68 px в высоту, радиус 16 px, серый `var(--n100)`, отступы поля 16 px, зазор иконка/текст 14 px; `.fi` 40×40 с логотипом 24×24. Текстовое значение уже содержит единицу доллара.
- **Запрещён дополнительный правый `.addon` / `USD` / суффикс / chevron**. Это не переключатель валютного счёта. Во всех исходящих банковских методах используется одна функция `uxSourceAccountField()`. Для новых вариантов вывода не копировать и не модифицировать её HTML вручную.
- Входящие пополнения не должны искусственно отображать списание с USD-счёта.

### 2. Иконки валют — общий оптический стандарт поля суммы

- У всех EUR/USD/GBP единый генератор `uxCurrencySymbol(code)`, но результат — **векторный** `<svg class="tf-currency-icon">`, а не типографические знаки `€/$/£`.
- Размер SVG **20×20 px**, `viewBox="0 0 24 24"`, `fill="none"`, `stroke="var(--n850)"`, `stroke-width="1.8"`, `stroke-linecap="round"`, `stroke-linejoin="round"`. Серый круг поля `.fi` **40×40 px**, у строк в шторке `.ri` 32×32 px; сама иконка остаётся **20×20**, не растягивается.
- Это та же сетка, что и у монеты `components/amount.html` и других `tfIconFor()`. Толщину и размер не подбирать индивидуально под шрифт или отдельную валюту; не рисовать символы текстом с `font-size:23px`.
- Применение без исключений: фиксированное `Валюта пополнения` в SEPA, `inCurrency` в SWIFT, фиксированное `Валюта получения` в SEPA, `outCurrency` в SWIFT, в том числе **каждая строка нижнего селектора** и выбранное значение после выбора. Для иных валют добавить новый SVG-путь в `uxCurrencySymbol` с тем же оптическим контрактом.
- `Страна получателя` сохраняет отдельный паттерн **круглого SVG-флага 24×24**, не подменять его значком валюты.

### 3. Мобильное положение навбара

- Эталон: `css/alt-vu-wallet.css`, `@media (max-width:740px)`: `.head {padding-top:calc(14px + env(safe-area-inset-top))}`.
- У `legacy.html` на мобильной ширине (в том числе внутри 390/430 px iframe) `.phone.tf-phone:not(.is-home) > .head` использует **те же 14 px плюс safe area**, отступы слева/справа 16 px, снизу 14 px. Нельзя оставлять десктопные `padding-top:52px` внутри мобильного экрана.
- На ширине браузера свыше 740 px сохраняется десктопный шаблон; избегать сдвигов самих элементов навбара дополнительными margin/padding на отдельных банковских экранах.
- Playwright: `tests/bank-qa/smoke.py` проверяет невидимый правый USD, идентичную SVG-геометрию валют и монеты, мобильный отступ на 390 и 430 px, а также исходные действия селекторов.

## Каноническая форма реквизитов получателя (SEPA/SWIFT)

**Область применения:** только шаг `out-recipient` исходящих международных переводов. Не переносить изменение на `out-config`, поля валют, суммы, страны и других исходных методов alt.vu. Рабочая разметка находится в `transfi-remittance/legacy.html`, стили — в `css/transfi-bank-altvu.css`.

- Все поля ввода получателя (единое поле «Имя и фамилия получателя», IBAN или номер счёта, SWIFT/BIC, название банка, назначение, уточнение назначения, дополнительные реквизиты) используют исходную оболочку `.fld.w.tf-field` **без левой `.fi` и без декоративных иконок**. Общий класс `.tf-recipient-field` ставится только на этом шаге. Отступы поля 16 px, высота 68 px, радиус 16 px, подпись и содержимое остаются без изменений. Шеврон у *интерактивного выбора назначения* сохраняется как индикатор действия, не как декоративная иконка поля.
- Основные реквизиты идут сначала; далее поле «Назначение перевода» и, при выборе «Другое», обязательное уточнение. **Последний элемент всей формы** — раскрываемое `<details class="tf-more tf-recipient-extra">`.
- Заголовок `<summary>` — самостоятельная строка «Дополнительные SWIFT-реквизиты» (для SEPA — «Дополнительные реквизиты»). Он **не помещён в отдельную белую карточку**: фон прозрачный, нулевые внутренние отступы у контейнера, нет его радиуса, тени, рамки или разделителей; только заголовок и компактный шеврон раскрытия.
- По умолчанию блок закрыт. По нажатию на заголовок открываются дополнительные **самостоятельные** белые поля `.fld.w.tf-recipient-field` в обычном вертикальном списке, без общей белой обёртки. SWIFT: routing code, адрес банка, адрес получателя, банк-корреспондент. SEPA: необязательный BIC и адрес получателя. Повторное нажатие сворачивает поля; введённые значения сохраняются.
- Изменение касается только **композиции формы**: имена ключей состояния `S`, DOM ID `f-* / wrap-*`, `checkRecipient()`, переходы на экран проверки и сохранение введённых значений остаются прежними.
- **Проверка**: `tests/bank-qa/smoke.py` контролирует отсутствие `.fi` в обязательных, условных и раскрытых полях; положение `details` последним непосредственным элементом формы; прозрачность внешнего блока; отдельные белые поля; работу раскрытия, закрытия и сохранение текста.



### ФИО, дополнительные реквизиты и условия доступности CTA

- На шаге `out-recipient` **ровно одно** поле `Имя и фамилия получателя`, ключ состояния `recipientName`, DOM ID `f-recipientName`. Два отдельных поля `firstName` и `lastName` в UX-прототипе **не отображаются**. Строка полностью и без автоматической перестановки используется на экране проверки и в статусах.
- Для предварительной UX-проверки необходимы минимум **два слова** в полном имени. Двух слов недостаточно, чтобы надёжно разделить составные имена и фамилии: формат отдельных API-полей и юридическое совпадение с банковским счётом необходимо проверять по `POST /v3/recipients/mandatory-fields` для выбранного направления. **Не разбивать пользовательский ввод на firstName/lastName автоматически в прототипе.**
- У всех полей внутри раскрываемых `details.tf-recipient-extra` **не показывать текст «· необязательно»** в подписи. Их необязательность остаётся частью сценария/схемы, сами значения не становятся required. При открытии и закрытии значения сохраняются.
- Кнопка `Продолжить` на `out-config` и `Проверить перевод` на `out-recipient` имеют `aria-disabled="true"` и класс `tf-inactive`, пока данные невалидны: серый фон, без акцентной тени. **Не использовать HTML `disabled` или `pointer-events:none`**: нажатие на визуально неактивную кнопку должно показать конкретную причину под кнопкой и через уведомление, а по возможности сфокусировать проблемное поле.
- Проверка `Продолжить`: сумма больше комиссии, сумма вместе с комиссией не превышает баланс. Проверка `Проверить перевод`: полное имя; IBAN для SEPA или номер счёта, BIC и банк для SWIFT; `purposeOther` обязательно, только если выбрано назначение «Другое». Дополнительные банковские поля не влияют на активность, пока не потребованы реальной схемой TransFi.
- При изменении полей / MAX / назначения активность CTA пересчитывается немедленно без потери фокуса и ранее введённых данных. После возврата с экрана проверки значение полного имени сохранено. Общий компонент кнопки и типографика остаются исходными.
- Автоматические сценарии: `tests/bank-qa/smoke.py` проверяет оба метода, нативный `aria-disabled` без атрибута `disabled`, ошибки по клику, поэтапное заполнение, `purposeOther`, раскрываемые поля, переход на review и возврат. `tests/bank-parity.mjs` проверяет полный SWIFT-проход с единым именем.



## Каноническая проверка и три экрана результата банковского перевода

Эталонные экраны из **полного исходного alt.vu**, восстановленного из архива Google Drive: `#v-transfer-check` («Проверьте перевод»), `#v-transfer-done` (успех P2P), `#v-dep-sbp-wait` (ожидание СБП), `#v-dep-sbp-out` (успех/ошибка СБП). Живые канонические примеры: [components/bankstatus.html](../components/bankstatus.html) и [UI Kit → Статусы и сообщения](../ui-kit/index.html#bankstatus).

### Проверка перевода (`out-review`)

- Заголовок навбара **«Проверьте перевод»**, не «Вывод SEPA/SWIFT».
- Крупная сумма вверху — **сумма поступления получателю** в валюте получения (SEPA: EUR; SWIFT: выбранная валюта). Подпись — полное имя получателя и метод.
- В карточке с реквизитами название строки **«Кому»**, а не «Получатель». Остальные реквизиты и назначение сохраняются.
- **Обе карточки используют один и тот же стиль строк:** верхняя карточка реквизитов имеет классы `.box.tf-review-box.tf-quote`, нижняя — `.box.tf-quote.tf-review-quote`. Левая колонка `.rt` в обоих блоках — основная подпись 15 px / 20 px, `font-weight:500`, `var(--n900)`; правая `.rv` — значение 15 px / 21 px, `font-weight:400`, `var(--n500)`, выравнивание вправо. Не возвращать старую инверсию цветов и насыщенности из `.tf-review-row`. Общая `tf-quote` обеспечивает идентичность оформления и разделителей.
- Над расчётом **нет отдельного заголовка «Расчёт»**. Карточка `.box.tf-quote` использует оригинальные строки `.row/.rt/.rv` в таком строгом порядке:
  1. «Сумма перевода» — сумма в EUR (или выбранной валюте получателя).
  2. «Курс» — `1 $ ≈ … EUR` для долларового исходного счёта.
  3. «Комиссия» — в долларах, со знаком `$`.
  4. **«Спишется со счёта»** — сумма в долларах, **`.row.tot`** с усиленным разделителем и жирным итогом, как в `#v-transfer-check`.
- В денежных значениях `USD` заменяется на `$`; **код валюты в самом селекторе** остаётся `USD` как название валюты (это не денежная сумма).
- Основная кнопка: **«Перевести {сумма в EUR}»**, динамически по текущему курсу и валюте получателя.

**Расчёт в демонстрационном прототипе:** `receive = amountUSD × fx`, `debitUSD = amountUSD + feeUSD`; комиссия списывается *сверху*, а не вычитается из получения. Вёрстка не должна маскировать эту разницу. Курс, тарифы и сама возможность маршрута в реальном приложении должны приходить из TransFi/бэкенда, а не из этого мокапа. Ранее `receive = (amountUSD − feeUSD) × fx` — несовместимо с текущим UX-правилом.

### Три **разных экрана** после подтверждения

- **Ожидание / `out-progress`:** оригинальная композиция `.sbp-wait` из СБП: круговой индикатор с иконкой часов, заголовок «Перевод обрабатывается», короткое пояснение и нижняя кнопка «На главную». Навбар сохраняется. Можно закрыть экран; финальное состояние обновляется callback. **Без таймлайна `.timeline/.track` и без таблицы операций.**
- **Успех / `out-success`:** оригинальный паттерн `#v-transfer-done` / `.hero.sbp-out`: без навбара, крупная лаймовая галочка, «Перевели {сумма в EUR}», подпись с ФИО получателя и методом. Снизу «На главную» и «Показать операцию».
- **Ошибка / `out-failed`:** оригинальный паттерн `#v-dep-sbp-out` для ошибки: без навбара, серый круг с крестиком, заголовок «Перевод не выполнен», пояснение. Кнопки «Попробовать ещё раз» (возврат к реквизитам) и «На главную».
- Дополнительное состояние комплаенс-проверки `out-held` использует композицию **ожидания**, а не отдельный таймлайн. Оно не считается успехом.
- Подтверждение **не означает зачисление**: сначала `pending`, а успех/ошибка/проверка возможны лишь при отдельном callback. Для UX-демонстрации их запускают **внешние** кнопки в `?qa=1`.
- Для одной синтетической операции использовать стабильный ID и обновлять статус в общей `PV.data['/operations']`. Кнопка «Показать операцию» открывает **нативный** `openOp()` / `#v-details` основного кошелька. Реальных платежей эти экраны не выполняют.

**Регрессия:** `tests/bank-qa/smoke.py` сравнивает SEPA/SWIFT, валюты, формулу суммы, порядок строк, `.row.tot`, кнопки и callback-детали; `tests/bank-parity.mjs` проверяет компоненты на 390 и 430 px, отсутствие таймлайна и переполнения.
